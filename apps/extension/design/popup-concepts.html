A · One clear action

Keep the current layout, but give it a hierarchy. One primary button, two secondary, and the batch tools go to a footer toolbar.

What changes

  • One primary button. "Update clip" is the only filled button. The chevron opens a menu with "Download .md" and "Save as new". The current UI has seven buttons of equal weight.
  • Status becomes a sentence. "Already saved · this will update it" replaces the small grey text after the site name. The user knows what the button does before they press it.
  • Capture is a real control. Article / Selection is a segmented toggle. The current "Clip format" row shows a checkmark but you cannot change it.
  • Suggestions are visible. Dashed chips show the daemon's category suggestions inline. One click adds one.
  • Batch tools move to a footer. Tabs, Search, and Links sit in a low-contrast toolbar with Settings. They no longer compete with Save.
  • Keyboard shortcut. ⌘↵ saves. The popup opens with focus on the category input.

Trade-offs

  • Least change to the code. Reuses the existing components. Lowest risk.
  • Still one long column. The preview is short and stays at the bottom.

B · Preview first

Show the user what they are about to save before they save it. The action bar is pinned to the bottom, so it stays in the same place on every page.

What changes

  • Preview card at the top. Title, site, excerpt, and facts about the extraction: mode, word count, reading time, image count. A bad extraction is obvious at a glance. Today the preview is the last thing on the page.
  • Status is specific. "In repository · date · path" tells the user which file will change. Today it says only "already in your repository".
  • Pinned action bar. Save, Bookmark, and Copy are always at the bottom edge. Muscle memory works. The bar does not move when the title wraps or categories grow.
  • Header carries the tools. Connection status on the left, three icon buttons on the right: Tabs, Search, Settings. "Save Links" moves into the Tabs page, where it belongs.
  • Clip format is information, not a control. It shows as a stat. If Selection mode is possible, a small "Use selection" link appears in the stats row.

Trade-offs

  • Best for confirming quality before saving. Good if extractions sometimes go wrong.
  • Needs word count and image count from the clipper. Small contract change.
  • Icon-only header buttons need tooltips. Slightly less discoverable than text.

C · Three modes, one window

The popup has three jobs: clip this page, clip many tabs, find a clip. Give each a mode. The user never leaves the popup for a full browser tab.

What changes

  • Mode tabs at the top. Clip, Tabs, Search. The Tabs badge shows the open tab count. Today "Save Multiple Clips" and "Search clips" open new browser tabs, which breaks the flow.
  • The Clip mode is minimal. Title, categories, one split button. Everything else lives in the menu with a shortcut: Bookmark, Copy, Download, Clip selection. The current UI shows all of these at once.
  • Tabs mode is inline. Check the tabs to save, set shared categories, press one button. "Links only" replaces the separate "Save Links" button. Rows already in the repository say "saved".
  • Search mode is inline. Type, see results, press Enter. ⌘K jumps to it from any mode.
  • Keyboard row. Shortcuts are printed at the bottom of the Clip mode, so the user learns them without a manual.

Trade-offs

  • Most usable for heavy users. Fewest clicks for every task.
  • Largest change. The Tabs and Search pages need compact versions inside the popup. The full pages can stay for wide layouts.
  • Hiding Bookmark and Copy in a menu adds one click for those actions. Shortcuts offset this.
